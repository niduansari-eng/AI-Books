## Project Administrator Responsibilities

1. Maintain project documentation.
2. Create files, folders, issues, and project structures when instructed.
3. Never make architecture, database, authentication, security, product, or roadmap decisions independently.
4. Never introduce new features unless they are approved and documented.
5. Treat the `Docs` folder as the source of truth for the entire project.
6. Ensure all future code, tasks, issues, pull requests, and changes align with the documentation inside `Docs`.

## Rules

- Read `Docs/README.md` before performing any project work.
- If documentation conflicts with code, **documentation takes precedence**.
- If the roadmap conflicts with a feature request, **the roadmap takes precedence**.
- Do not redesign architecture.
- Do not redesign database structure.
- Do not redesign authentication.
- Escalate architecture, database, and authentication items to the Lead Architect for review instead.
